# 公众号排版模板 · 藏蓝 + 红 · 章节分隔

一套可直接粘进微信公众号编辑器的排版模板：**白底正文 + 藏蓝加粗层级 + 红色章节分隔条**，配 壹/贰/叁 三张章头分隔条和一张 THE END 收尾条。

所有数值不是估的，是从一篇已发文章的发布页 HTML 里**逐条读内联样式实测**出来的（读法见 [layout-spec.md](layout-spec.md)）。

## 规格速查

| 项目 | 值 |
|---|---|
| 容器 | `max-width:677px` 居中，背景 **#FFFFFF** |
| 字体族 | `"PingFang SC NEW", system-ui, -apple-system, BlinkMacSystemFont, "Helvetica Neue", "Hiragino Sans GB", "Microsoft YaHei UI", "Microsoft YaHei", Arial, sans-serif` |
| 正文 | **15px** / 行高 **1.75em** / 字间距 **0.544px** / 颜色 **#595959** |
| 段边距 | `margin: 0 16px`（文字与图片同一边距） |
| 段间距 | 靠一个空段 `<br>` 撑开约 26px，不是 `margin-bottom` |
| 层级行 | 藏蓝 **#1F4E6E** + 加粗，**字号不变，仍是 15px** |
| 强调 | 橙红 **#FF4C00** + 加粗，只用于人名/关键词首现 |
| 居中 | 仅三类：署名、END 后两句收尾语、图片；其余正文一律左对齐 |
| 章节分隔条 | 2160×340（**6.35:1**），显示宽 **62%** → 渲染 **400×63** |
| THE END 条 | 2160×161（**13.42:1**），显示宽 **62%** → 渲染 **400×30** |
| 头图 | 1800×766（2.35:1），放正文最上方、署名之前，**不缩进**（渲染 677×288） |

> **比例与宽度（2026-09-17 定）**：原始素材 2160×540（4:1），645px 列宽下渲染高 **161px ≈ 6 行正文**，章头压得太重；END 条更浪费——内容只占原画布 12%，上下 474px 全是空白。两步收敛：
> 1. **改扁画布**：章头条 4:1 → **6.35:1**（不能裁，只能缩内容贴到更扁画布）；END 条裁白 → **13.42:1**。
> 2. **收窄显示宽度**：全宽 → **62%**（400px），视觉更含蓄。
>
> 合起来：章头条 161px → **63px**，END 161px → **30px**。脚本见 `tools/make_separators.py`；显示宽度是 `build.py` 里的 `DIVIDER_WIDTH`。

## 文件说明

```
index.html            自包含可复制版 —— 4 张分隔条已 base64 内嵌，浏览器打开 → 全选复制 → 粘进公众号
index.relative.html   可读版 —— 图片走 assets/ 相对路径，方便看源码和改结构
layout-spec.md        排版规范：实测数值、层级规则、图文序列、不要继承的坑
compare-divider-ratios.html  分隔条比例四选一决策存档（静态记录，2026-09-17 定案采用 ④）
build.py              生成脚本：python3 build.py 重新生成上面两个 HTML
tools/make_separators.py  分隔条比例调整：--head / --end-band / --restore
assets/               4 张分隔条 PNG（已改成 6.35:1 / 13.42:1）
assets/original-4x1/  原始 4:1 版本，随时可还原
```

`index.html` 与 `index.relative.html` 都由 `build.py` 生成，**改结构请改 `build.py`，不要直接改 HTML**。

## 调整分隔条比例与宽度

**比例**（改素材，需重新生成 HTML）：

```bash
python3 tools/make_separators.py --head 340 --end-band 161   # 当前用的比例
python3 tools/make_separators.py --head 540                  # 回到 4:1 的高度感
python3 tools/make_separators.py --restore                   # 完全还原原始 4:1
python3 build.py && python3 build.py --plain                 # 改完重新生成 HTML
```

**宽度**（只改 CSS，不动素材）：编辑 `build.py` 顶部的 `DIVIDER_WIDTH`，再跑一次 `build.py`。

```python
DIVIDER_WIDTH = 62   # 100 = 与正文同宽；62 = 收窄（当前）
```

两种处理方式不同，**不要混**：

- **章头条（壹/贰/叁）**：图形本身占满画布，**不能裁**。变扁只能「把内容等比缩小 → 贴到更扁的画布上居中」，所以比例 = 新画布宽高比，两侧会有留白。
- **END 条**：内容是居中的一条细带，直接裁掉上下留白即可，不缩放。

> 当时比较了四档（原始全宽 / 只收宽度 / 只改扁 / 改扁＋收窄），最终采用第 ④ 档。四档的真实尺寸对照与判定依据存档在 [`compare-divider-ratios.html`](compare-divider-ratios.html)，包含已弃用的方案，便于日后回溯。

## 用法

1. 用浏览器打开 `index.html`
2. `Ctrl/Cmd + A` 全选 → `Ctrl/Cmd + C` 复制
3. 粘进公众号编辑器（图片会一起带过去，因为已经 base64 内嵌）
4. 把正文里 `【】` 包住的占位说明逐段替换成你的内容

> **为什么图片要内嵌**：公众号编辑器粘不了 `file://` 或相对路径的图片，图片会直接丢。base64 data URI 才能跟着复制走。

## 替换清单

| 位置 | 要做什么 |
|---|---|
| 署名 | 「作者 \| 小铭」——改成你想要的署名 |
| 头图 | 模板里用 HTML 注释标了位置，**需要你自己插一张 2.35:1（1800×766）的图** |
| 人物图/配图 | 同样用注释标出，需要自己插，建议带 16px 边距 |
| 三张分隔条 | 已内嵌，**不要动**；若要改章数，从 `assets/` 取原图另配 |
| 正文 `【】` | 逐段替换。`【】` 里写的是这一段的功能和字数建议 |
| 结尾两句 | 「原创不易，感谢有你！」「一起转发出去，让更多人看到。」**保留，居中**（2026-09-17 用户定）。属转发引导 footer、AI 检测敏感件，风险已告知；要临时去掉就把 `build.py` 的 `WITH_FOOTER` 改成 `False` |

## 三条硬约束

1. **正文背景必须纯白。** 4 张分隔条是无透明通道的白底 PNG，换成 `#F5F5F7` 之类的底色，分隔条会露出一个白方块。
2. **层级只用一种颜色。** 全篇靠 `#1F4E6E` 加粗（字号不变）做层级，不要自己加字号差、色块或边框，一加就破。
3. **正文末尾不加签名行。** 结尾就停在两句收尾语上，不附「我是小铭，专注…」这类签名。

---

## 章节切法

模板里是 **3 章**。经验值：**每 800 字左右切一次**，按叙事段落切，**不是每个小标题都给分隔条**。分隔条给太密，文章看起来会像目录。

- 壹 → 人物与经历（含反常识转折）
- 贰 → 方法（这件事是怎么做成的）
- 叁 → 给读者的可操作动作
